# SW 개발비 견적서 (KOSA 기능점수 간이법)

요구사항/제안서를 **기능점수(FP) 간이법** 견적서(.xlsx)로 변환한다. 산출물은 KOSA
"소프트웨어사업 대가산정 가이드" 표준 4시트 구조이고, 모든 금액은 **엑셀 수식**으로
들어가 고객이 셀을 바꾸면 자동 재계산된다.

산식·FP유형·보정계수의 근거는 `references/kosa-fp-method.md`,
입력 포맷은 `references/spec-schema.md` 를 참고. **둘 다 작업 시작 전에 읽는다.**

## 워크플로우

### 1. 입력 확보
제안서·요구사항·기능 목록을 확보한다. 없으면 사용자에게 (a) 대상 시스템/모듈,
(b) 외부 연계 기관 수(연계복잡성), (c) 보안 요구수준, (d) 이윤·할인 정책,
(e) 목표 금액(있으면)을 묻는다.

### 2. 기능 분해 (핵심)
시스템을 **애플리케이션 → 세부업무 → 단위프로세스** 3단계로 분해하고, 각
단위프로세스에 FP 유형을 부여한다. 동사로 유형을 판별한다:

| 단위프로세스 성격 | FP유형 | 가중치 |
|---|---|---|
| 등록·입력·설정·요청·전송·실행·승인 | **EI** | 4 |
| 대시보드·리포트·결과 산출·시각화·모니터링·통계 | **EO** | 5.2 |
| 조회·검색·필터·비교 (단순 조회) | **EQ** | 3.9 |
| ~데이터·마스터·저장소·원장 | **ILF** | 7.5 |
| ~연동·Import·외부 API·타 기관 연계 | **EIF** | 5.4 |

세부업무 하나는 보통 **EI 몇 개 + EO 몇 개 + EQ + ILF 1~2개 + (외부연계 시 EIF)**
조합이 자연스럽다. 실제 화면/기능 단위로 쪼개되 억지로 채우지 않는다.

### 3. 보정계수·상용 파라미터 결정
`correction`(연계/성능/운영/보안 각 1~5), `profit_rate`, `discount_rate`,
`direct_costs`(직접경비), `expenses`(실비)를 정한다. **사용자가 명시한 값을 그대로
존중**하고, 안 정해진 것만 합리적 기본값(보정계수 2, 이윤 0.10, 할인 0)으로 둔다.
금융·블록체인 등 민감 도메인은 보안 4~5가 일반적.

### 4. 목표 금액이 있으면 규모 역산
"8억 정도로 맞춰줘" 같은 목표가 있으면, 먼저 필요한 총FP를 역산해 기능 분해의
양을 가늠한다:
```bash
python scripts/calc_fp.py --target 800000000 --security 5
```
→ 필요 총FP와 대략적 단위프로세스 개수를 알려준다. 그 규모에 맞게 2번의 기능
분해를 늘리거나 줄인다(단가는 고시값이라 고정 — **기능 규모가 유일한 정직한 레버**).
억지로 의미 없는 기능을 채우지 말고, 도메인상 실재하는 기능으로 채운다.

### 5. spec.json 작성 → 빌드 → 미리보기
`references/spec-schema.md` 형식으로 spec.json 을 쓴다. 그다음:
```bash
python scripts/calc_fp.py spec.json                          # 금액 미리보기(엑셀 불필요)
python scripts/build_estimate.py spec.json --output 견적서.xlsx
```
미리보기 금액이 목표와 어긋나면 spec 의 기능 분해/보정계수를 조정해 다시 빌드한다.

### 6. 결과 보고
최종 견적(부가세 별도/포함), 총FP, 적용 보정계수, 직접비를 표로 요약하고,
**어떤 가정(보정계수·이윤·할인·직접비)을 썼는지** 명시한다. 기능 목록을 어디서
도출했는지(제안서/사용자 입력) 출처도 밝힌다.

## 핵심 주의사항

- **직접비 더블카운트**: 이 스킬 템플릿은 원본 KOSA 양식의 직접비 이중합산 버그를
  수정해 두었다(`최종견적!K5 = 상세비용!K8+K9`). 직접비는 한 번만 반영된다.
- **단가 고정**: 기능점수당 단가(605,784원)는 KOSA 고시값. 금액을 맞추려고 단가를
  임의로 바꾸지 말고 기능 규모/보정계수로 조정한다. (고시 갱신 시 `unit_price` 로 교체)
- **실비는 분리**: 실비(Pass-through)는 할인 미적용. 직접경비와 구분해 `expenses` 에.
- **검증**: 빌드 후 `calc_fp.py` 의 미리보기 금액과 엑셀이 일치해야 한다(동일 산식).
  LibreOffice가 있으면 추가로 재계산 검증 가능하나 필수는 아니다.

## 파일

- `assets/kosa_fp_template.xlsx` — 빈 4시트 표준 템플릿(수식·서식 내장, 직접비 버그 수정본)
- `scripts/build_estimate.py` — spec.json → 견적서.xlsx
- `scripts/calc_fp.py` — 금액 미리보기 / 목표금액 역산
- `examples/sto_platform_spec.json` — STO 플랫폼 견적 예시(307개 단위프로세스)
- `references/kosa-fp-method.md` — 산식·FP유형·보정계수표
- `references/spec-schema.md` — 입력 스키마
